# AGENTS.md

## Project overview

VS Code extension **npm-outdated-plus** (`publisher: rentalhost`, license ISC) that highlights
outdated packages directly in `package.json` files and offers code actions to update them. Fully
compatible with **npm**, **pnpm** and **bun**.

- **Stack:** TypeScript (^7.0.2) compiled and bundled by **tsdown** into a single minified CJS file
  at `out/extension.cjs`; tests run on **Vitest** (^4.1.11); lint/format on the **Oxc** suite
  (oxlint + oxfmt) driven by `@rheactor/rheactor-oxc-config`.
- **Entry point:** `src/extension.ts` (`activate`), declared as `"main": "./out/extension.cjs"` with
  activation event `onLanguage:json`.
- **Runtime dependency:** `semver` only (bundled). `@rheactor/rheactor-core` (GitHub dependency) is
  also embedded by the bundler.
- **Folder structure:**

| Path                      | Purpose                                                                 |
| ------------------------- | ----------------------------------------------------------------------- |
| `src/*.ts`                | Source modules, PascalCase named (one concern per file).                |
| `src/extension.ts`        | Extension activation.                                                   |
| `src/plugin.json`         | Extension name used to build command IDs and settings prefix.           |
| `src/__mocks__/vscode.ts` | Vitest mock of the `vscode` API.                                        |
| `src/TestUtils.ts`        | `vscodeSimulator()` harness shared by integration tests.                |
| `locales/`                | l10n bundles: `bundle.l10n.jsonc` (English reference), `.pt-br`, `.es`. |
| `assets/icon.png`         | Marketplace icon.                                                       |
| `images/`                 | README screenshots.                                                     |
| `out/`                    | Build output (`extension.cjs`), not committed.                          |
| `.vscode/`                | Debug/task configs (`Run Extension` launches an extension host).        |

## Mandatory rules

- **Language:** code, identifiers and comments in English; user-facing strings always through
  `l10n.t(...)`, with keys registered in `locales/bundle.l10n.jsonc` (English reference first, then
  `bundle.l10n.pt-br.json` / `bundle.l10n.es.json`). Settings descriptions live in
  `package.nls.{locale}.json`.
- **Module naming:** one module per concern, PascalCase filename matching its main export
  (`PackageManager.ts`, `PackageInfo.ts`, ...); only the extension entry stays lowercase
  (`extension.ts`) alongside colocated `*.test.ts` files.
- **Imports:** use Node-style subpath imports `#/*` (mapped to `./src/*` by the `imports` field in
  `package.json`, mirrored in `tsconfig.json` paths and the Vitest alias). External APIs come from
  bare specifiers (`vscode`, `semver`, `@rheactor/rheactor-core`, node builtins with `node:`
  prefix). Import groups are separated by blank lines: external packages first, then `#/*`.
- **Settings:** every contributed setting uses the `npm-outdated-plus.` prefix derived from
  `plugin.json`; access them through helpers in `src/Settings.ts`, never raw
  `workspace.getConfiguration` calls elsewhere.
- **Commands:** IDs are `${packageName}.commandName` constants exported from `src/Command.ts`.
- **Async style:** async/await; promise-returning helpers (`promiseLimit`, `lazyCallback`,
  `waitUntil`, `requestSafe`) live in `src/Utils.ts`.
- **README.md** content sections are maintained by the `/create-agents` skill; authored prose
  (features, usage, configuration tables) is preserved verbatim during updates.
- **CHANGELOG.md** follows Keep a Changelog format normalized by `/create-agents`.

## Testing policy

- Framework: **Vitest** (`vitest.config.ts`), `globals: true`, run with `bun run test`.
- Test files are colocated next to the code under test as `*.test.ts` (`src/Utils.test.ts`,
  `src/PackageManager.test.ts`, `src/extension.test.ts`).
- The `vscode` API is mocked via `vi.mock("vscode")` aliasing to `src/__mocks__/vscode.ts`;
  filesystem/process side effects are mocked through `node:fs/promises` and `node:child_process`
  module mocks driven by `src/TestUtils.ts`.
- Every fixed bug requires a regression test reproducing it before the fix.
- No coverage threshold is configured; keep meaningful assertions per test (`expect.assertions(n)`
  is used throughout the suite).

## Documentation format

`README.md` follows the application template: badge and tagline, screenshot, **Features**,
**Configuration** table (setting, description), **Usage**, **Stack**, **Folder structure**,
**Scripts & commands**. Authored sections are preserved word for word; generated sections are
regenerated by `/create-agents` from `package.json` and the repository layout.

## Dependencies

- Package manager: **bun** (`bun.lock`). Install with `bun install`.
- Zero new runtime dependencies without justification; the extension ships self-contained
  (`--no-dependencies` packaging), so anything added gets bundled into `out/extension.cjs`.
- Shared lint config comes from `github:rheactor/rheactor-oxc-config`; core utilities from
  `github:rheactor/rheactor-core`.

## Environment variables

None. The project does not read environment variables at runtime; the local `.env` file is ignored
by both git and packaging (`.vscodeignore`).

## Build and publish

- `bun run build` emits the minified CJS bundle to `out/extension.cjs` (tsdown,
  `deps.neverBundle: ["vscode"]` keeps the host API external).
- Packaging/publishing require the global **vsce** CLI installed via npm
  (`npm install -g @vscode/vsce`): `bun run vscode:package` produces the `.vsix`,
  `bun run vscode:publish` publishes. Both rely on the `vscode:prepublish` hook, which runs the
  build exactly once.

## Quality gates

Always run through `bun run <script>` (never call binaries directly):

| Script      | Command                                                |
| ----------- | ------------------------------------------------------ |
| `build`     | `tsdown`                                               |
| `lint`      | `bun run typecheck && bun run oxlint && bun run oxfmt` |
| `typecheck` | `tsc --noEmit`                                         |
| `test`      | `vitest --run`                                         |
| `oxlint`    | `oxlint ./src`                                         |
| `oxfmt`     | `oxfmt --check ./src ./locales ./.vscode`              |
